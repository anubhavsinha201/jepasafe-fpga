What this is, and what it isn't

The sensor trace, the fixed-point logits, the class decision and the LED pattern are all real: recorded motion through the synthesised design, with the pin assignments the bitstream actually uses. What it cannot show is a physical MPU6050 on a physical bus — I²C timing against real silicon, 3.3 V levels and sensor drift stay untested until the board exists. Replaying recorded data is exactly the substitute the verification plan called for.

Six channels, not nine

UCI HAR ships body_acc, body_gyro and total_acc. This trains on total_acc + body_gyro — exactly what an MPU6050 outputs. body_acc is gravity-filtered, so using it would mean reimplementing a Butterworth filter in RTL before inference.

No input normalisation

Training on raw physical units keeps on-device preprocessing to one shift and one multiply: accelerometer is count >>> 3, gyro is (count × 279) >>> 10. A per-channel affine transform would have cost far more fabric.

Why Keras and not PyTorch

hls4ml 1.3.0's PyTorch parser has no transpose handler, and Conv1d → LSTM needs two of them, because Conv1d is channels-first while LSTM wants (batch, time, feature). Keras Conv1D is already channels-last, so the identical architecture converts with no transposes at all. The recurrence was never the blocker.

Don't count primitives

A first pass used get_cells -filter {REF_NAME =~ DSP*} and reported 486 DSPs — an apparent nine-fold blowout. On UltraScale+ a DSP48E2 is nine leaf cells, and 54 × 9 = 486 exactly. report_utilization is the only authority.

Verification without hardware

Three honest columns

The board's absence changes what can be claimed, so it is worth being exact about which claims survive.

Verified

no board needed
  • Fixed-point accuracy over all 2,947 test windows, by bit-accurate C simulation.
  • The preprocessing path — 128 of 128 beats matched against the core's own captured AXI-Stream payload, zero out of tolerance.
  • Every hand-written RTL module, by unit testbench under Icarus. Seven pass.
  • The I²C master, against a behavioural MPU6050 slave that ACKs its address and keeps a register file.
  • Fit and timing closure on the real part, with a routed bitstream to show for it.

Blocked

environment, not design
  • RTL-versus-C co-simulation. xelab.exe is blocked by this machine's Device Guard policy, and xelab builds the snapshot xsim loads. vivado, xsim, xvlog and xsc all run — only the elaborator is refused.
  • The Icarus fallback reaches five of six pipeline stages clean, then breaks: Vitis RTL assumes FPGA power-up-zero, and pooling emits 113 words while conv2 has supplied only 48 — the dataflow FIFO handshake is not honoured.
  • Both robust routes are one step away: Verilator, which is 2-state by design, or an exception for the elaborator.

Unprovable

needs real hardware
  • Real MPU6050 behaviour. I²C timing against physical silicon, 3.3 V levels, bus capacitance, sensor offset. A slave model tests the master's logic, not the bus.
  • Real-world accuracy. 90.9% is thirty subjects with a waist-mounted phone; nothing here measures a different body position or sensor.
  • Power. Requires the board's rails.
  • Fall detection — but that is a dataset gap, not a hardware one. See below.

A green test that meant nothing for eighteen days

The repository held a co-simulation report reading Verilog | Pass. Its vector directory was empty, so the testbench had fallen through to a fill_zero branch and classified a window of zeros — all five result lines byte-identical. It proved the RTL does not deadlock and nothing more. Nothing in the hls4ml flow warns you; the testbench fails safely and silently.

There is no AXI-Lite register map, so the processing system could not start it by writing a register even if it wanted to. ap_start is tied high and the kernel free-runs. The final Dense emits its wide accumulator type, so a host decoding real logit values must use 17 integer bits — irrelevant for argmax, which is monotonic.

Two bugs the slave model caught

Both would have been invisible on real hardware until nothing worked at all.

  • The repeated START sent the wrong address. S_START overwrote the shift register, so the read transaction re-sent the write address.
  • The first transaction after reset never happened. The state machine assumes each state is entered at phase 0 — true after a STOP, false on the first pass, where the bit-phase divider sits wherever it happens to. S_START ran its phase-3 case first and never generated a START condition, so the device was never woken and the master logged a NACK.
Measured, not assumed

What the numbers actually taught

Each of these was established by running the tools, and each changed a decision.

01 · ONE WORD

layers.ReLU() is not free

222,550 LUT

hls4ml maps layers.ReLU() to a parametrized thresholdedrelu carrying a live threshold compare per element. The two activation blocks alone measured more than the whole device. Activation('relu') is identical mathematics — ReLU's default threshold is zero — and accuracy is unchanged.

02 · STRUCTURE, NOT TUNING

Reuse factor cannot save a conv layer

298,000 LUT

Under io_parallel, reuse shares multipliers within a dot product but still unrolls across all 124 output positions. The fix is structural: io_stream gives Conv1D a line buffer, so area scales with filter count instead of window length.

03 · THE SURPRISE

Table BRAM scales with width, not depth

32 → 128 BRAM

Cutting the LSTM's activation table_size from 1024 to 256 propagates correctly into the generated project and changes resource usage by exactly zero. What does change it is hidden width, linearly: the ROM is replicated for parallel access across the 4 × hidden gate values.

04 · A PART REJECTED

An LSTM cannot fit a 9k-LUT FPGA

612% BRAM

The original target was a Tang Nano 9K. The LSTM's sigmoid and tanh lookup tables alone need 32 block RAMs — more than that part has in total — before a single weight is stored. Gated recurrence needs both nonlinearities, so this is structural rather than a tuning problem.

05 · TRUST, CALIBRATED

HLS estimates lean conservative

2.2× high on LUT

Against post-route reality: LUT over by 2.2×, BRAM by 1.7×, DSP exact. Every "will it fit" decision in this project was made against logic and memory figures roughly twice the truth — which means the full-size model's rejection at 104% block RAM deserves re-measuring.

06 · THE COST OF SIZE

13.8× the parameters buys 1.18 points

90.91 → 92.09%

The 64/64/64 model reaches 92.09% with 60,486 parameters, but measures 654 BRAM_18K — 104% of the device — and fails on block RAM alone. Until the unused URAM is put to work, 16/16/16 is the only configuration measured to fit.

Limitations

What this is not

It does not detect falls

Despite the name, the model classifies six ordinary activities: walking, upstairs, downstairs, sitting, standing, laying. UCI HAR contains no fall, impact or assault class, so ALERT_CLASSES defaults to all-zero — nothing raises an alert, because declaring any of six everyday activities an emergency would be false. Closing this needs EdgeFall or a collected fall set and a retrain. The board's absence neither causes this nor would fix it.

The name predates the architecture. The project began as a Transformer JEPA design; that was dropped for a 1D CNN + LSTM, which converts cleanly through hls4ml. The name survives in the package and the RTL because renaming ripples for no functional gain.

Board facts, read rather than assumed

Every pin came out of the installed ZCU104 board file. Three contradicted what had been written down.

AssumedActual
125 MHz single-ended clock300 MHz differential pair, DIFF_SSTL12 — divided by an MMCM

PMOD voltage unknownPL I²C is LVCMOS33 — an MPU6050 needs no level shifting

The PL UART is LVCMOS18, so a 3.3 V Bluetooth module on that path would need shifting.

Reproducing it

Toolchain

No QKeras and no separate quantisation step: precision is an hls4ml configuration value, so the fixed-point model only ever exists inside the generated project.

Four commands

python -m jepasafe.cnnlstm_keras --epochs 40
python -m jepasafe.export_hls
cd hls/jepasafe && vitis_hls -f ../../scripts/csim.tcl
vivado -mode batch -source scripts/vivado_top_impl.tcl

Then bash scripts/sim.sh runs the seven Icarus testbenches in about thirty seconds, and vivado vivado/top_impl/post_route.dcp opens the routed design on the die.
